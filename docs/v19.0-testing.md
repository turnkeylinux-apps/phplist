## Source and update decision

Debian Trixie does not package the phpList application. The appliance therefore
installs phpList 3.7.0 from the official phpList SourceForge release channel.
The official [download page](https://www.phplist.org/download-phplist/) names
3.7.0 as the stable release. SourceForge publishes
`phplist-3.7.0.sha256`; the build requires its archive entry to match the pinned
digest
`0b1c2eae6a7fd617d18438d97d47714b4cbfdf3e6b2abab8a154e17d28ec89de`
before extraction.

Debian supplies PHP 8.4, MariaDB, Apache, Postfix, cron, and all enabled PHP
extensions. Trixie no longer provides `php-imap`. phpList 3.7.0 includes the
Webklex IMAP implementation used by its newer bounce-processing path, so the
appliance does not introduce an unmaintained PHP extension source.

The supported application update path is:

```sh
turnkey-phplist-update --check
turnkey-phplist-update --apply
```

The check reads the official stable download page, downloads the corresponding
release and published SHA-256 file, verifies the archive, reports the installed
and eligible versions, and leaves the installation unchanged. The apply path
is root-only. It retains code and MariaDB backups under
`/var/backups/phplist`, installs the verified official release while preserving
`config.php`, and runs phpList's command-line database upgrader.

kernel, installer, hardware, or live boot behavior, so a separate phpList ISO
boot is not required.

## Known limitations

Docker runtime validation does not exercise installer, kernel, hardware, or ISO
boot behavior. Those inherited paths are covered by the Core 19 baseline.

## Deferred issues

- Debian Trixie removed the legacy PHP IMAP extension. phpList 3.7.0 bundles a
  Webklex IMAP fallback for its newer core, while legacy pages that call PHP's
  `imap_*` functions directly remain unavailable. The appliance README does not
  promise legacy mailbox import or bounce pages, and the supported list,
  subscriber, queue, and sending flows do not depend on them.
